<objective>
Expose the two Phase 13 endpoints through a single authenticated entry point and register the new Python codebase in the Firebase hosting/functions configuration.

Purpose: SEC-01 requires authentication on every backend entry point; this plan is where the boundary becomes real. The endpoints are deliberately thin and read-only — `sharepoint_me` proves the auth and tenancy chain end-to-end, and `sharepoint_upload_intent` proves validation and rate limiting — so Phase 14 can add Graph calls behind a proven door.
Output: `main.py` with `_authenticated`, `sharepoint_me`, `sharepoint_upload_intent`; a two-codebase `firebase.json`; and an AST-based guard test that fails if any future handler exports without the decorator.

Decisions made in-plan (D-13-J):
- `GET /sharepoint/me` returns the resolved `AuthContext` projection (`uid`, `email`, `companyId`, `isAdmin`, `role`) and nothing else — no claims dump, no token material.
- `POST /sharepoint/upload-intent` accepts `{"filename", "mime", "size"}` and returns `{"normalizedFilename", "mime", "sizeBytes", "maxBytes", "rateLimit": {"remaining", "resetAt"}}`, with `maxBytes` echoing the configured ceiling so the client can pre-check.
- No Microsoft Graph call exists in Phase 13; `sharepoint_upload_intent` stops at the policy decision. Phase 14 adds the upload.
- Method allow-listing is explicit: a non-GET on `/me` and a non-POST on `/upload-intent` return 405 through `ApiError`, not through the framework default.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → Cloud Functions HTTPS endpoint | Unauthenticated and malformed requests arrive here first. |
| Firebase Hosting/deploy config → production functions | A mis-shaped `firebase.json` silently drops a deployed function. |
| Handler → policy modules | Every request path must pass through auth, validation, and limiting in that order. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-28 | Spoofing | `_authenticated` coverage | critical | mitigate | AST guard test requires `_authenticated` on every `on_request` function and cross-checks `AUTHENTICATED_ENDPOINTS`; fails on any future unprotected handler. |
| T-13-29 | Information Disclosure | endpoint responses and logs | high | mitigate | Responses built only through `private_json`/`private_error`; logs built only through `build_log_event` with hashed identifiers; test asserts no `error.message`/`str(exc)`/`traceback`. |
| T-13-30 | Denial of Service | `sharepoint_upload_intent` ordering | medium | mitigate | Validation runs before `RateLimiter.check`, so invalid payloads consume no budget; limiter failure fails closed; explicit 405 for wrong methods. |
| T-13-31 | Tampering | `firebase.json` codebase list | medium | mitigate | Both sources asserted present; hosting block unchanged; reporting predeploy preserved so nothing is silently undeployed. |
| T-13-32 | Elevation of Privilege | outbound call introduced early | low | accept | No Graph/HTTP client is imported in this phase; guard test would flag an import addition, which is the intended review trigger for Phase 14. |
