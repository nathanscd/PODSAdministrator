<objective>
Implement the AES-256-GCM envelope encryption module that will hold Microsoft Graph refresh tokens at rest, with key-version support so keys can be rotated without losing existing rows.

Purpose: SEC-04 requires that refresh tokens never sit in Firestore as readable text and that a tampered or tenant-swapped ciphertext is detected rather than silently used. This module is the single cryptographic boundary for Phase 13; Phase 14 stores and Phase 15 reads through it.
Output: `crypto.py` with `EncryptedBlob`, `encrypt_blob`, `decrypt_blob`, `CryptoError`, `UnknownKeyVersionError`, and a test suite covering nonce uniqueness, AAD binding, tamper detection, and key-version dispatch.

Decisions made in-plan:
- Envelope field names are fixed as `algorithm`, `keyVersion`, `nonce_b64`, `ciphertext_b64`, `aad`, `updatedAt` so Phase 14 can persist the dict directly into Firestore without a translation layer.
- AAD is a deterministic string of the form `v1|<tenantId>|<purpose>` built by `build_aad(tenant_id, purpose)`; callers pass `purpose` (for example `graph-refresh-token`), never a user-supplied value.
- Key material comes from `secret_provider.get_crypto_key(key_version)`; this module never reads environment variables itself.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Firestore document storage → application | Ciphertext and envelope metadata are attacker-readable; plaintext must remain unrecoverable without the Secret Manager key. |
| Tenant A data → Tenant B request path | A copied envelope must not decrypt under another tenant's context. |
| Secret Manager → process memory | Key material is used per call and must not be retained or logged. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-04 | Information Disclosure | `crypto.py` plaintext handling | high | mitigate | AES-256-GCM with 12-byte `os.urandom` nonce per call; no plaintext or key in any field, message, or log; tests assert ciphertext substrings absent from errors. |
| T-13-05 | Tampering | envelope rows in Firestore | high | mitigate | AAD binds `v1|tenantId|purpose`; `InvalidTag` → `CryptoError("decrypt_failed")`; tamper and tenant-swap tests. |
| T-13-06 | Spoofing | key-version confusion during rotation | medium | mitigate | `decrypt_blob` dispatches on the envelope's `keyVersion`; unsupported version raises `UnknownKeyVersionError` instead of falling back to the active key. |
| T-13-07 | Repudiation | nonce reuse | high | mitigate | Fresh nonce per encryption verified by a 200-sample uniqueness test and a parallel 100-sample test. |
</threat_model>
