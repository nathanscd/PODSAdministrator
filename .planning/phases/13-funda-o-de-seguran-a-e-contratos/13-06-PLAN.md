<objective>
Build the two guard rails every SharePoint request passes through: an allow-list logger that cannot record secrets, and an upload validator plus Firestore-backed fixed-window rate limiter that reject bad payloads before any Microsoft call happens.

Purpose: SEC-07 requires that logs never carry tokens or secrets; SEC-08 requires upload validation and rate limiting so a compromised client cannot flood the tenant or push oversized or disallowed content. Both are shared policy objects used by 13-07's endpoints and by Phase 14's upload path.
Output: `logging_utils.py` with `LOG_ALLOWED_KEYS`, `SENSITIVE_KEY_FRAGMENTS`, `scrub_payload`, `redact_value`, `build_log_event`; `validation.py` with the MIME/size policy, `UploadMetadata`, `validate_upload_metadata`, `RateLimitDecision`, `RateLimiter` protocol, `FirestoreRateLimiter`, `rate_limit_key`; and two test suites including a concurrency test for the limiter.

Decisions made in-plan:
- Rate limiting uses Firestore fixed-window counters keyed by `sha256(uid|endpoint|windowIndex)` in `sharepointRateLimits` (D-13-C), updated inside a transaction so concurrent requests cannot both consume the last slot.
- The limiter fails closed only for instrumented failure: if the counter read raises, the request is denied with `RATE_LIMITED` rather than allowed, because an unreadable limiter must not become an open door.
- Filename normalization strips directory components, rejects `.`/`..`, collapses control characters, preserves unicode letters and digits, limits the base name to 200 characters, and preserves a single extension from the allow-list.
- The MIME allow-list is the minimum set a document workflow needs: `application/pdf`, the three OOXML document types, `image/png`, `image/jpeg`, `text/plain`, `text/csv`. Executable, archive, script, and SVG types are excluded deliberately.
- Numeric contract (no rounding anywhere): sizes are integers and are compared as integers, with `size > max_bytes` rejected and `size == max_bytes` accepted — a strict greater-than comparison, never a rounded or floating-point conversion. The window index is `floor(now / window_seconds)` computed with integer division on integers, never on floats. `remaining` is `max(0, limit - count)` so an over-counted window cannot go negative, and `reset_at` is the window end epoch plus one window expressed as an integer second. No half-up/half-to-even tie-breaking exists in this module because no fractional quantity is ever computed; a JSON number with a fractional part (for example `10.5`) is rejected as an invalid size rather than truncated.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client-supplied filename/MIME/size → backend | All three values are attacker-controlled and influence downstream Microsoft calls. |
| Backend → log sink | Logs are broadly readable by operators and retained; anything written there is effectively public within the org. |
| Client → rate-limit budget | A single caller can attempt unbounded requests; the limiter is the only backpressure point. |
| Backend → Firestore counters | Counter documents are shared per tenant and mutated concurrently. |
