<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Human gate → `requirements.txt` | Install only after explicit `blocking-human` approval from 14-02. |
| Cloud Function → Microsoft identity platform | MSAL owns HTTPS, state, PKCE and token cache; backend holds client secret via Secret Manager. |
| Cloud Function → Microsoft Graph | Access token sent only to `graph.microsoft.com` with timeout and minimal response mapping. |
| MSAL cache → Firestore envelope | Serialized cache crosses into crypto before persistence; frontend never sees it. |
| Config → Fail-closed | Redirect URI and tenant allowlist are required identifiers, not trusted defaults. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-SC | Tampering | `msal==1.39.0` install | high | mitigate | `depends_on: 14-02` blocks this plan until human approval; no other package is added. |
| T-14-08 | Tampering | `msal_client.build_confidential_client` | critical | mitigate | Authority/tenant and Secret Manager secret are injected only from verified settings; no handler-supplied values. |
| T-14-09 | Information Disclosure | `msal_client` logs | critical | mitigate | No logging of token, cache, nonce, claims or ciphertext; tests use fakes. |
| T-14-10 | Spoofing | `ms_allowed_tenant_ids` | high | mitigate | Comma-parsed allowlist required by `require_identifiers`; callback validates `tid` in 14-04. |
